# Building Custom Gutenberg Blocks in This Project

A beginner-friendly, step-by-step guide to adding custom Gutenberg blocks, using a worked example: a **Featured Product** block that displays a single WooCommerce product with live price and stock.

## Chosen approach

Custom blocks live in their own dedicated plugin under `web/app/plugins/`, built with `@wordpress/scripts` (`wp-scripts`) — the official WordPress tooling — rather than in the theme via Vite.

**Why:**

1. **Blocks are content, not presentation.** WordPress's own model expects content (including the blocks used to build a page) to survive a theme switch. Registering blocks from the theme means they — and any page built with them — break if the theme ever changes. Registering from a plugin means they keep working regardless of the active theme.
2. **It matches this project's existing conventions.** Every piece of logic here (`shop-checkout`, `shop-payment-gateways`, `shop-account`, `shop-api`) lives in its own dedicated plugin. The theme (Sage) is used for presentation/layout only. Blocks are logic + content, so a plugin is the consistent home for them.
3. **`wp-scripts` is purpose-built for blocks; Vite is not.** It already understands JSX, `@wordpress/block-editor` components, and `block.json` auto-registration with zero configuration, because the WordPress core team maintains it specifically for this.
4. **Running two build tools isn't a problem.** Vite (theme assets) and `wp-scripts` (blocks plugin) solve different jobs and don't conflict — this is a normal setup.

## Step 0: Static vs. dynamic blocks

A block can render its content two ways:

- **Static** — JavaScript generates HTML once, and that HTML is frozen into the database when the page is saved.
- **Dynamic** — PHP generates the HTML fresh, every single time the page loads.

A Featured Product block **must** be dynamic. The price and stock status can change after the page is built — a static block would keep showing the price from the day it was added, even after the item goes out of stock. Dynamic rendering means the PHP fetches live WooCommerce data on every page load.

## Step 1: Scaffold the plugin

From the project root:

```bash
cd web/app/plugins
npx @wordpress/create-block@latest --no-plugin shop-blocks
```

`--no-plugin` skips the auto-generated plugin boilerplate so the structure can match this project's conventions (like `shop-account`, `shop-api`) instead.

## Step 2: Resulting folder structure

```
web/app/plugins/shop-blocks/
├── shop-blocks.php          ← the plugin's entry file (like shop-account.php)
├── package.json             ← npm dependencies for building block JS
├── src/
│   └── featured-product/
│       ├── block.json       ← describes the block
│       ├── edit.js          ← what the admin sees/edits
│       ├── index.js         ← registers the block on the JS side
│       └── render.php       ← generates the HTML shown to shoppers
└── build/                   ← compiled output (generated by wp-scripts, don't edit by hand)
```

## Step 3: `block.json`

The block's ID card — `src/featured-product/block.json`:

```json
{
  "apiVersion": 3,
  "name": "shop/featured-product",
  "title": "Featured Product",
  "category": "widgets",
  "icon": "cart",
  "description": "Displays a single WooCommerce product with live price and stock.",
  "attributes": {
    "productId": { "type": "number", "default": 0 }
  },
  "editorScript": "file:./index.js",
  "render": "file:./render.php"
}
```

The important part is `attributes.productId` — the one thing this block remembers is *which* product to show. Everything else (name, price, stock) is looked up live, not saved.

## Step 4: Editor experience (`edit.js`)

What the admin sees while building the page — a dropdown to pick a product:

```jsx
import { useBlockProps } from '@wordpress/block-editor';
import { SelectControl, Spinner } from '@wordpress/components';
import { useSelect } from '@wordpress/data';
import { store as coreStore } from '@wordpress/core-data';

export default function Edit({ attributes, setAttributes }) {
  const blockProps = useBlockProps();
  const products = useSelect(
    (select) => select(coreStore).getEntityRecords('postType', 'product', { per_page: -1 }),
    []
  );

  if (!products) {
    return <div {...blockProps}><Spinner /></div>;
  }

  return (
    <div {...blockProps}>
      <SelectControl
        label="Choose a product"
        value={attributes.productId}
        options={[
          { label: 'Select a product...', value: 0 },
          ...products.map((p) => ({ label: p.title.rendered, value: p.id })),
        ]}
        onChange={(value) => setAttributes({ productId: Number(value) })}
      />
    </div>
  );
}
```

No `save.js` is needed — this is a dynamic block, so PHP handles the actual output.

## Step 5: Frontend output (`render.php`)

Runs on every page load, on the real site:

```php
<?php
$product_id = $attributes['productId'] ?? 0;

if (! $product_id) {
    return;
}

$product = wc_get_product($product_id);

if (! $product) {
    return;
}
?>
<div <?php echo get_block_wrapper_attributes(); ?>>
    <a href="<?php echo esc_url($product->get_permalink()); ?>">
        <?php echo wp_kses_post($product->get_image()); ?>
        <h3><?php echo esc_html($product->get_name()); ?></h3>
        <span><?php echo wp_kses_post(wc_price($product->get_price())); ?></span>
        <?php if (! $product->is_in_stock()) : ?>
            <span>Out of stock</span>
        <?php endif; ?>
    </a>
</div>
```

`wc_get_product($product_id)` runs fresh every time — that's the "live data" part.

## Step 6: Register the block in PHP

In `shop-blocks.php`, the main plugin file:

```php
<?php
/**
 * Plugin Name: Shop Blocks
 */

namespace App\ShopBlocks;

defined('ABSPATH') || exit;

add_action('init', function () {
    register_block_type(__DIR__ . '/build/featured-product');
});
```

`register_block_type()` reads `block.json` and wires everything up.

## Step 7: Build

Blocks are written in JSX, which browsers can't run directly — `wp-scripts` compiles it:

```bash
cd web/app/plugins/shop-blocks
npm install
npm run build
```

This produces the `build/` folder that `register_block_type()` points at.

## Step 8: Activate and test

```bash
wp plugin activate shop-blocks
```

Open any page in the block editor, search for "Featured Product," drop it in, pick a product from the dropdown, and publish. The page should show that product's live price and stock.
